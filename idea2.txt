2. Application Technology Stack

প্রথমে উপযুক্ত প্রযুক্তি নির্বাচন করে সংক্ষিপ্ত Architecture Plan তৈরি করবে।

প্রস্তাবিত Stack:

- Mobile Framework: Flutter এবং Dart।
- Local Database: SQLite, প্রয়োজন অনুযায়ী Drift বা সমমানের নির্ভরযোগ্য সমাধান।
- Secure Storage: Android Keystore-সমর্থিত নিরাপদ Storage।
- Charts: Lightweight chart library।
- Notifications: Local Notifications।
- AI: Google Gemini API এবং Generic OpenAI-compatible Provider Adapter।
- Networking: নির্ভরযোগ্য HTTP Client।
- Local AI: উপযুক্ত ছোট মডেলের জন্য llama.cpp, ONNX Runtime অথবা সমর্থিত অন্য কোনো On-device Inference Engine।
- Testing: Unit Tests, Widget Tests এবং Integration Tests।

এগুলো বাধ্যতামূলকভাবে সব একসঙ্গে ব্যবহার করতে হবে এমন নয়। যেটি সবচেয়ে হালকা, নির্ভরযোগ্য এবং Android 6 থেকে নতুন Android সংস্করণে বাস্তবসম্মতভাবে কাজ করবে, সেটি নির্বাচন করবে।

অপ্রয়োজনীয় বড় লাইব্রেরি, ভারী Animation Engine, অপ্রয়োজনীয় Background Service এবং অপ্রয়োজনীয় Network Request এড়িয়ে চলবে।

3. Android 6–16 এবং 32-bit/64-bit Compatibility

অ্যাপটি Android 6.0 থেকে Android 16 পর্যন্ত যত বেশি সম্ভব বাস্তব ডিভাইসে চালানোর জন্য তৈরি করবে।

Compatibility requirements

- Android 6.0 (API 23) থেকে শুরু করে Compatibility লক্ষ্য করবে।
- নতুন Android সংস্করণগুলোর জন্য আধুনিক SDK ও নিরাপত্তা নীতি অনুসরণ করবে।
- Google Play-তে প্রকাশের জন্য বর্তমান Target SDK requirement অনুসরণ করবে; ২০২৬ সালের ৩১ আগস্ট থেকে নতুন অ্যাপ ও আপডেটের জন্য Android 16 / API 36 বা তার বেশি Target SDK প্রয়োজন।
- পুরোনো Android ডিভাইসে Unsupported API ব্যবহার করবে না।
- প্রয়োজনীয় API ব্যবহারের আগে Version Check করবে।
- Runtime Permission সঠিকভাবে পরিচালনা করবে।
- Android 6-এর পুরোনো WebView, কম RAM, কম CPU এবং দুর্বল ইন্টারনেটের সীমাবদ্ধতা বিবেচনা করবে।
- 32-bit ARM এবং 64-bit ARM ডিভাইসের জন্য উপযুক্ত Build Variant তৈরি করবে, যেখানে ব্যবহৃত Framework ও Native Dependencies সমর্থন করে।
- Native Library-এর ABI compatibility যাচাই করবে।
- কোনো 64-bit-only Native Dependency ব্যবহার করলে সেটি 32-bit ফোনে কীভাবে পরিচালিত হবে, তা নির্ধারণ করবে।
- APK/AAB-এর আকার কমানোর জন্য ABI Splits, Resource Shrinking এবং উপযুক্ত Code Optimization ব্যবহার করবে।
- Android 6–16 জুড়ে সব ফিচার সমানভাবে কাজ করবে—এমন মিথ্যা নিশ্চয়তা দেবে না। যে ফিচার কোনো OS বা হার্ডওয়্যারে সমর্থিত নয়, সেখানে সুন্দর Fallback দেখাবে।

বিশেষভাবে মনে রাখবে: Android 6–16-এ অ্যাপের সাধারণ UI ও Routine Tracking চালানো এবং সব ফোনে একই Local AI Model চালানো এক বিষয় নয়। AI মডেলের জন্য CPU, RAM, Architecture এবং Storage আলাদাভাবে যাচাই করতে হবে।

সাধারণ Gemini REST API-এর Base Endpoint:

"https://generativelanguage.googleapis.com/v1beta"

Model List এবং Generate Content API-এর বর্তমান পদ্ধতি যাচাই করে ব্যবহার করবে।

Default Provider-এর জন্য ব্যবহারকারীকে Endpoint লিখতে হবে না।

শুধু API Key Configure করলেই যেন সাধারণ ব্যবহার শুরু করতে পারে।

অ্যাকাউন্টের Quota, Model Availability, Billing এবং API Key Permission অনুযায়ী Feature সীমিত হতে পারে। Free Access বা Unlimited Usage-এর মিথ্যা নিশ্চয়তা দেবে না।

D. API Key Security

API Key কখনো Source Code-এ Hardcode করবে না।

Git Repository-তে API Key রাখবে না।

API Key Local Secure Storage-এ রাখবে।

Log, Crash Report বা Analytics-এ API Key প্রকাশ করবে না।

যদি কোনো Provider-এর API Key Client App-এ ব্যবহারের কারণে ঝুঁকিতে পড়তে পারে, তাহলে সেই ঝুঁকি স্পষ্টভাবে জানাবে এবং সম্ভব হলে Restrictable Key অথবা Secure Backend Proxy ব্যবহারের বিকল্প দেখাবে।

ব্যবহারকারীর নিজস্ব API Key থাকলে সেটি তার Configuration হিসেবে সংরক্ষিত থাকবে। কোনো Provider-এর কাছে অপ্রয়োজনীয়ভাবে অন্য Provider-এর Credentials পাঠাবে না।

প্রাথমিক Model Package-এর জন্য 10 MB-কে একটি Size Target হিসেবে বিবেচনা করবে।

তবে একটি গুরুত্বপূর্ণ প্রযুক্তিগত সীমাবদ্ধতা আছে: মাত্র 10 MB-এর একটি Model-কে আধুনিক, শক্তিশালী General-purpose Chat Model-এর সমতুল্য ধরে নেওয়া যাবে না। Quantization, Vocabulary, Architecture এবং Context Length অনুযায়ী কার্যক্ষমতা বদলে যায়।

সুতরাং:

- 10 MB-এর কাছাকাছি Lightweight Model বা Tiny Model পরীক্ষা করবে।
- উপযুক্ত 10 MB Model না পাওয়া গেলে বাস্তব Model Size উল্লেখ করবে।
- Model-এর কার্যক্ষমতা পরীক্ষা ছাড়া “Powerful AI” বলে প্রচার করবে না।
- Tiny Model-এর জন্য সীমিত কাজ, FAQ এবং সহজ Routine Query-তে Focus করবে।
- উন্নত Offline Chat-এর জন্য ঐচ্ছিক বড় Model Download-এর ব্যবস্থা রাখবে।
- Model Download-এর আগে Download Size, প্রয়োজনীয় Storage, সম্ভাব্য RAM Requirement এবং Supported Architecture দেখাবে।

16. Medication & Scalp Care Safety

অ্যাপের Routine Engine-এ নিম্নলিখিত Product Template থাকবে:

- Ketoconazole 2% Shampoo।
- Minoxidil 5%।
- Derma Roller / Microneedling।

ব্যবহারকারী এগুলোকে নিজের Routine হিসেবে যোগ, Edit বা Remove করতে পারবে।

Safety Rules

- Ketoconazole Shampoo-এর ব্যবহার চিকিৎসক বা পণ্যের নির্দেশনা অনুযায়ী Schedule করতে হবে।
- Minoxidil-এর Dose, Frequency এবং ব্যবহারবিধি ব্যবহারকারীর অনুমোদিত নির্দেশনা অনুযায়ী হবে।
- ডিফল্টভাবে নির্দিষ্ট Dose বা Schedule-কে সবার জন্য চিকিৎসাগতভাবে সঠিক বলে ঘোষণা করবে না।
- Derma Roller / Microneedling-এর ক্ষেত্রে Needle Length, Sterilization, Skin Condition এবং Infection Risk গুরুত্বপূর্ণ।
- Microneedling-এর পর Minoxidil ব্যবহারে Irritation এবং Systemic Absorption-এর ঝুঁকি বিবেচনা করতে হবে।
- Derma Roller-এর দিন Minoxidil ব্যবহার স্বয়ংক্রিয়ভাবে অনুমোদন করবে না।
- চিকিৎসকের নির্দেশনা ছাড়া Microneedling ও Minoxidil-এর জন্য নিরাপদ বিরতির সময় নিজে থেকে নিশ্চিতভাবে নির্ধারণ করবে না।
- ব্যবহারকারীকে চিকিৎসকের পরামর্শ অনুযায়ী Schedule সেট করার সুবিধা দেবে।
- স্ক্যাল্পে ক্ষত, সংক্রমণ বা তীব্র জ্বালা থাকলে Routine চালিয়ে যাওয়ার আগে চিকিৎসা-পরামর্শ নেওয়ার সতর্কতা দেখাবে।

অ্যাপটি কোনো রোগ নির্ণয় বা চিকিৎসা-নির্দেশ প্রদানকারী সফটওয়্যার হিসেবে উপস্থাপিত হবে না। এটি মূলত Personal Routine Management এবং Tracking Tool।

CR Growth QS — Additional Prompt: Default Weekly Hair-Care Routine & Smart Schedule Integration

1. Main Instruction

Integrate this specification into the existing CR Growth QS project as a separate additional instruction. Do not rewrite, replace, remove, or unnecessarily modify any feature or requirement in the original master prompt.

The routine specified below must be configured as the app's default primary weekly routine. It must appear automatically in the Routine Tracker, Home Dashboard, calendar, daily checklist, notifications, and weekly progress reports.

The routine must cover all seven days of the week, Monday through Sunday. Users must be able to track each scheduled task as Pending, Completed, Skipped, or Rescheduled.

2. Default Routine Items

Configure these three separate routine items:

1. Ketoconazole 2% Shampoo
   
   - Frequency: Three scheduled days per week.
   - Preferred time: Afternoon.
   - Default reminder time: 2:00 PM.
   - Must not appear as a daily task on all seven days.

2. Minoxidil 5%
   
   - Frequency: Every day, seven days per week.
   - Morning reminder: 9:30 AM.
   - Night reminder: 11:00 PM.
   - Display two separate daily checklist items, one for the morning and one for the night.
   - On Thursday, the morning Minoxidil task remains scheduled. The afternoon and evening rules for the other items must be handled separately.

3. Derma Roller / Microneedling
   
   - Frequency: Once per week.
   - The default scheduled day is Thursday, subject to the safety rules below.
   - The app must show this as a separate task, not as part of the Ketoconazole or Minoxidil checklist item.

3. Seven-Day Weekly Schedule

Generate a complete Monday-to-Sunday schedule using the following requirements.

- Minoxidil 5%: Show the morning task at 9:30 AM and the night task at 11:00 PM every day, Monday through Sunday.
- Ketoconazole 2% Shampoo: Schedule three afternoons per week, with Thursday included as one of the three days.
- Derma Roller / Microneedling: Assign one weekly session, with Thursday as the intended default day.
- Do not schedule Ketoconazole on every day.
- Do not create duplicate reminders for the same routine item and time.
- Keep the schedule consistent across the Home Dashboard, calendar, notifications, and weekly report.

Thursday Special Rule

Thursday must be handled as a special routine day in the weekly planner:

- Morning: Show the Minoxidil 5% task at 9:30 AM.
- Afternoon: Show the Ketoconazole 2% Shampoo task at 2:00 PM only if it is safe and appropriate to use that day.
- Derma Roller / Microneedling: Display a separate reminder for the intended session, with a configurable afternoon/evening time.
- If the user has a clinician-approved instruction to avoid Ketoconazole on the microneedling day, automatically mark the Thursday shampoo task as withheld for safety and do not issue its reminder.
- Do not automatically schedule or recommend Minoxidil or Ketoconazole application immediately before or after microneedling. The app must respect an appropriate clinician-specified waiting period.

The user's intended Thursday condition is that the morning Minoxidil reminder remains visible, the weekly Derma Roller task is scheduled, and the Ketoconazole task is handled according to the safety restriction. Do not silently claim that all three treatments can safely be used on the same day.

Following Day Rule

From Friday onward, resume the normal recurring schedule, while respecting any safety-related waiting period associated with microneedling. Do not permanently remove or shift the weekly routine merely because one Thursday task was withheld.

The scheduler must distinguish between:

- A regularly scheduled task.
- A task temporarily withheld for safety.
- A task skipped by the user.
- A task rescheduled by the user.

Do not count a safety-withheld task as user non-compliance.

4. Important Medical Safety Requirements

This application is a routine tracker, not a prescribing system. Do not invent a medical prescription or assume that the user has received professional approval for microneedling.

- Preserve the requested product names and intended frequencies as user-configured routine preferences.
- Clearly distinguish a user's preferred schedule from a clinician-confirmed treatment plan.
- Minoxidil 5% twice daily must not be presented as universally appropriate for every formulation or individual. Display the product-label or clinician-directed dosage and usage instructions.
- Minoxidil should not be applied to irritated, injured, or freshly microneedled skin. Do not assume that skipping it for only one day is always sufficient; the appropriate waiting period depends on the procedure and medical advice.
- Do not automatically instruct the user to apply Ketoconazole shampoo to freshly microneedled or irritated skin.
- Make it possible to mark a task as “Withheld for Safety” without losing the weekly schedule.
- Provide a configurable clinician-approved waiting period after microneedling, and prevent incompatible reminders during that period.
- If the user has not confirmed that the combination and timing are appropriate, show a brief safety notice and allow the schedule to be reviewed before activating treatment reminders.

The application must not claim that the routine is medically approved unless the user explicitly records that confirmation.

5. Smart Routine Scheduler

Implement a reusable routine scheduling system rather than hardcoding reminders into individual screens.

Each routine item should support:

- Name and product strength.
- Scheduled weekdays.
- Preferred time.
- Enabled/disabled state.
- Completion status.
- Safety restrictions.
- Optional clinician instructions.
- Reminder notification settings.
- Last completed date.
- Weekly completion statistics.

Store the routine configuration locally so that it works offline. Preserve the same schedule after app restarts and device reboots. If the original project already uses a database or notification system, integrate with it rather than creating a conflicting duplicate system.

Use the device's local timezone. Handle notification permissions, missed reminders, daylight-saving changes where applicable, and Android battery restrictions gracefully.

6. Home Dashboard and Calendar

Display the following information clearly:

- Today's date and weekday.
- Today's scheduled routine items and their times.
- Separate morning, afternoon, and night sections.
- A completion checkbox for each task.
- A distinct safety-withheld state.
- The next scheduled reminder.
- Today's completion percentage.
- Weekly completion progress.

The seven-day calendar must make it easy to identify which three days contain Ketoconazole, which day contains the weekly Derma Roller task, and which Minoxidil reminders occur every day.

7. Weekly Report and Routine Editing

Provide a weekly report that shows:

- Minoxidil morning completion.
- Minoxidil night completion.
- Ketoconazole completion on its three scheduled days.
- Derma Roller completion on its weekly scheduled day.
- Missed, skipped, rescheduled, and safety-withheld tasks separately.

Do not count unscheduled Ketoconazole days as missed tasks. Do not count a safety-withheld task as a missed dose or user failure.

Allow the user to edit routine times and weekdays. However, preserve the requested default schedule on first setup unless the user changes it. Any schedule modification must update the dashboard, calendar, notifications, and reports consistently.

8. Acceptance Criteria

The implementation is complete only when all the following tests pass:

1. The weekly planner displays all seven days.
2. Minoxidil morning and night reminders are configured for every day, at 9:30 AM and 11:00 PM respectively.
3. Ketoconazole is scheduled exactly three times per week, including Thursday in the default configuration.
4. The Derma Roller task appears once per week, with Thursday as the intended default day.
5. Thursday safety restrictions prevent inappropriate overlapping treatment reminders.
6. The schedule resumes normally on subsequent days while respecting any required waiting period.
7. Safety-withheld tasks are not counted as user failures.
8. Offline tracking, app restarts, notifications, and weekly reports remain consistent.
9. The original CR Growth QS features continue working without regressions.
10. The app never represents this user-preferred routine as a medically validated prescription.

Deliver the implementation as an integrated addition to the existing CR Growth QS project, preserving the original master prompt and all previously specified functionality.
